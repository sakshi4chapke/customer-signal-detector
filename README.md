# Intelligent Customer Signal Detector

AI-powered early-warning prototype that identifies at-risk customers by fusing
behavioural, billing, and conversational signals into a ranked, explained
priority list for a customer operations team.

**Status:** working POC — full pipeline and dashboard complete.

---

## What it does

Customer ops teams are usually reactive: by the time a complaint escalates or
a cancellation arrives, the chance to intervene has passed. Warning signs exist
earlier — in usage drops, payment failures, NPS scores, and support chats —
but they live in separate systems and are reviewed manually.

This prototype continuously monitors those signals, correlates them, and
outputs:

- A **ranked priority list** of customers who need attention
- A **risk score** (0–100) and urgency band (Low / Medium / High / Critical)
- **Plain-English rationale** with verbatim evidence from transcripts
- A **recommended retention action**, owner team, and SLA

---

## How it works

```
Raw CSVs  →  Data Cleaner  →  Stage 1 (parallel)
                                 Behaviour Agent  ·  Billing Agent  ·  Sentiment Agent (Gemini)
                                      ↓ merge signals
                             Risk / Scoring Engine  →  Recommendation Agent  →  Streamlit Dashboard
```

| Stage | What happens | Uses AI? |
|---|---|---|
| **Clean** | Fix duplicates, invalid values, missing fields | No |
| **Extract** | Three specialist agents read structured data and chat logs | Sentiment agent only |
| **Score** | Weighted deterministic formula combines all signals | No — LLM never assigns numbers |
| **Recommend** | Suggest action (e.g. IMMEDIATE_CALL), team, SLA, talking points | Optional (rules fallback always available) |
| **Display** | Operations dashboard with priority list, drill-down, analytics | No |

**Key design choice:** scoring is deterministic arithmetic. The LLM extracts
signals and writes language; the same input always yields the same risk score.

---

## Signal categories

| Source | Agent | Examples |
|---|---|---|
| **Behaviour** | Rule-based | Inactivity, usage decline, low NPS, NPS silence, support spike, unresolved backlog |
| **Billing** | Rule-based | Payment failure, overdue invoice, contract renewal approaching |
| **Conversation** | Gemini LLM | Churn intent, competitor mention, escalation language, repeat issue, high frustration |

Each signal has a severity (low / medium / high / critical) and supporting
evidence. Weights and thresholds are configurable in `src/config.py`.

---

## Dataset

Synthetic data generated by `src/data_generator.py` (seed 42, fully
reproducible). Six customer archetypes are planted with deliberately different
signal profiles:

| Archetype | Design intent | Typical risk |
|---|---|---|
| healthy_loyal | Baseline — active, satisfied | Low |
| quiet_drifter | Silent churn — bad behaviour, quiet transcripts | High |
| loud_but_stable | Angry in chat, healthy usage | Medium |
| billing_wounded | Payment failures, billing disputes | High / Critical |
| escalating_churner | Explicit exit intent | Critical |
| new_fragile | Poor onboarding, short tenure | Medium / High |

| File | Rows | Purpose |
|---|---|---|
| `data/raw/customers.csv` | 203 → 200 clean | Structured behavioural + billing data |
| `data/raw/conversations.csv` | 487 | Multi-turn support transcripts |
| `data/raw/answer_key.csv` | 200 | Ground-truth labels — evaluation only, never used in scoring |
| `data/raw/data_dictionary.csv` | 31 | Column definitions |

## Full pipeline — regenerate from scratch

```bash
# 1. Generate synthetic data (optional — data/raw/ already included)
python src/data_generator.py

# 2. Clean and validate
python src/data_cleaner.py

# 3. Analyse transcripts with Gemini (consumes API quota)
python notebooks/05_run_sentiment.py

# 4. Generate recommendations for top-risk customers (optional LLM)
python notebooks/07_recommendations.py

# 5. Run full orchestrator → writes pipeline_output.json
python notebooks/08_run_pipeline.py

# 6. Launch dashboard
streamlit run app/dashboard.py
```

**Cached mode (default):** steps 3–5 replay stored LLM output — no API key
needed. Use this for demos and development.

**Live mode:** pass `--live` to `08_run_pipeline.py` to call Gemini during the
run. Recommended only for small batches due to free-tier quota limits.

**Health check:** `python diagnose_llm.py` verifies your API key and model name.

## Example input and output

### Input — structured row (`customers.csv`)

```csv
customer_id,name,segment,last_login_days_ago,usage_pct_change_30d,support_tickets_90d,nps_score,failed_payments_90d
CUST0014,Example Customer,Mid-Market,58,-68.2,0,,0
```

### Input — conversation snippet (`conversations.csv`)

```text
Customer: Password reset link isn't arriving. Can you resend?
Agent: Sent a fresh link — please check spam.
Customer: Got it, thanks.
```

Mundane text — no explicit churn language. Behavioural signals carry the weight.

### Output — assessment (from `pipeline_output.json`)

```json
{
  "customer_id": "CUST0014",
  "risk_score": 65.3,
  "risk_level": "High",
  "confidence": 1.0,
  "signals": [
    {"name": "INACTIVITY", "severity": "critical", "source": "behaviour",
     "evidence": "No login for 58 days"},
    {"name": "USAGE_DECLINE", "severity": "critical", "source": "behaviour",
     "evidence": "Usage down 68.2% vs prior 30 days"},
    {"name": "NPS_SILENCE", "severity": "low", "source": "behaviour",
     "evidence": "No NPS response on record"}
  ],
  "recommendation": {
    "action": "PROACTIVE_CHECKIN",
    "priority": "P2",
    "owner_team": "Customer Success",
    "sla_hours": 72,
    "explanation": "Customer showing strong disengagement signals despite minimal support contact..."
  }
}
```

### Output — priority list row (`pipeline_summary.csv`)

```csv
rank,customer_id,name,risk_score,risk_level,action,owner_team
42,CUST0014,Example Customer,65.3,High,PROACTIVE_CHECKIN,Customer Success
```

For contrast, a vocal but engaged customer (`loud_but_stable`) scores **33.5
Medium** despite angry transcripts — proving multi-signal correlation beats
sentiment-only detection.

## Assumptions and limitations

- **Synthetic planted data** — metrics validate detection logic as designed,
  not real-world predictive accuracy.
- **Missing NPS is a signal**, not a gap — non-response indicates disengagement.
- **200 customers** — sufficient to demonstrate ranking; too small to train a model.
- **Absolute thresholds** — production would use per-customer relative baselines.
- **Cached LLM output** — demo runs without API quota; live mode available for fresh analysis.

## Evaluation snapshot (planted data)

| Metric | Result |
|---|---|
| Precision @10 | 100% |
| Recall (High + Critical flag) | 88% |
| quiet_drifter mean score | 62.8 (High) |
| loud_but_stable mean score | 31.9 (Medium) |
| Customers flagged Critical + High | 88 (54 Critical, 34 High) |

The quiet drifter outranks the vocal complainer — the core proof that
behavioural signals are weighted correctly.
